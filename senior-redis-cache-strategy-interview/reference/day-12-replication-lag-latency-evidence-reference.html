Day 12 · 빠른 참고

Redis Replication과 Latency — 지연의 분모와 복제 보장

복제 차이를 시간 지연으로 오해하지 않고, client·서버·복제 지연을 구분한다.

핵심 판단 기준

  1. 쓰기/읽기 대상과 가시성 요구부터 확인.
  2. replication ID가 같은 offset은 바이트 위치; 차이는 초가 아님.
  3. pool·RTT·명령 실행·host/event-loop·sync를 분리.
  4. WAIT 반환 개수 확인; 특정 replica 읽기·무손실을 보장하지 않음.

복습용 용어

replication offset
동일 복제 이력의 스트림 바이트 위치.
backlog
부분 재동기화를 위해 primary가 보관하는 최근 복제 스트림.
SLOWLOG
서버의 명령 실행 시간이 threshold를 넘은 기록.
WAIT
앞선 쓰기의 replica 확인 수를 제한된 시간 동안 기다리는 명령.

다시 확인

  • Redis — Replication — 비동기 복제·이력·부분/전체 동기화
  • Redis — Latency Diagnosis — 네트워크·서버·host 지연 분리
  • Redis — SLOWLOG — 명령 실행 시간의 측정 범위
  • Redis — WAIT — 복제 확인 수와 보장 한계
