에이전트 간 handoff — 상태·권한·복구 계약

에이전트를 늘리는 것보다 handoff 계약을 명확히 하는 것이 중요하다. 다음 에이전트가 무엇을 알고 어떤 행동을 할 수 있는지 제한한다.

오늘의 학습 결과: 위임 입력·출력 스키마와 재시작 가능한 조정 흐름을 만든다

면접 질문

코드 변경 에이전트가 조사 에이전트의 결과를 받아 파일을 수정하고 테스트하는 harness를 설계해 보세요.

실무 상황: 조사와 수정은 병렬화할 수 있지만 같은 파일을 동시에 바꾸면 충돌한다. tool call은 비용이 들고 일부 agent가 timeout·잘못된 결과를 낼 수 있다.

왜 묻는가: multi-agent를 역할 이름만 분리하지 않고 컨텍스트 공유·권한·검증·취소 전파까지 설계하는지 본다.

전제 개념

handoff는 단순히 대화 내용을 복사하는 것이 아니라 작업 소유권과 상태를 다른 실행 주체에 넘기는 경계다. 입력 스키마, 기대 산출물, 제한된 tool permission이 필요하다.

LLM 출력은 신뢰할 수 있는 실행 명령이 아니다. 파일 변경이나 네트워크 작업은 검증·승인 경계 뒤에서만 실행하고, 각 agent가 전체 권한을 공유하지 않게 한다.

답변 사고 순서

  1. 분해 가능성: 작업 간 dependency와 공유 파일·상태를 그려 병렬로 안전한 부분만 분리한다.
  2. handoff schema: 목표, 관련 파일, 불변조건, 근거 링크, 제한, 완료 판정을 구조화한다.
  3. 격리: agent별 tool allowlist와 worktree/파일 경계를 두고 credential은 최소화한다.
  4. 조정·검증: 중간 결과를 검증자에게 전달하고 실패·timeout·부분 완료 상태를 기록한다.
  5. 복구: idempotent task id, checkpoint, 취소 전파, 재실행/사람 승격 조건을 정한다.

케이스 풀이와 답변 예시

조사 agent는 읽기 전용으로 영향 파일과 근거를 반환하고, 구현 agent는 지정한 파일 범위에서만 수정한다. 마지막 reviewer가 계획·diff·요구사항을 대조한 뒤 병합 여부를 판단한다.

작업을 조사와 수정으로 나누기 전에 같은 파일을 건드리는지와 순서 의존성을 확인하겠습니다. handoff에는 재현 조건, 근거, 대상 경로, 금지된 작업, 완료 기준을 포함하고 각 agent에 최소 tool 권한을 주겠습니다. 결과는 자동 병합하지 않고 파일 경계와 요구사항을 검사하며, timeout 뒤 재실행할 때 중복 side effect가 나지 않도록 task id와 checkpoint를 사용하겠습니다.

답변에서 드러나는 점: 평행성보다 실패 격리와 작업 추적을 먼저 정의한다.

Trade-off

선택얻는 점비용·위험
단일 agent 순차 실행상태와 책임이 명확하고 충돌이 적다.독립 작업의 latency와 컨텍스트 한계가 커질 수 있다.
다중 agent 병렬 실행독립적인 조사·검토의 wall time을 줄일 수 있다.handoff 비용, 불일치, 중복 작업, 파일 충돌과 비용이 증가한다.
공유 대화 전체 전달배경 정보를 넓게 제공한다.불필요한 토큰·민감 데이터 노출·지시 혼선을 늘린다.

흔한 오해

agent 수가 많을수록 작업은 더 빠르고 정확하다.

병렬화 이득은 독립성에서 나오고, 결과 통합·검증 비용이 이를 넘어설 수 있다. 정확성은 권한 제한과 검증 계약이 만든다.

직접 풀어보기

두 agent가 같은 `auth.py`를 수정할 계획을 냈습니다. 실행을 어떻게 재구성하고 결과를 통합하겠습니까?

예시 풀이와 피드백 보기

공유 파일 변경을 순차화하거나 한 agent에 수정 ownership을 준다. 다른 agent는 읽기 전용 검토로 전환하고, 파일 경계/인터페이스 계약을 합의한 뒤 단일 diff를 검증한다.

자가 피드백: agent 수가 아니라 병렬 가능한 dependency와 소유권을 말했는가?

Senior follow-up

  1. agent가 완료라고 보고했지만 실제 파일 변경이 없으면 어떤 검증이 잡나요?
  2. 하위 agent가 prompt injection된 파일을 읽었다면 tool 권한 경계를 어떻게 지킵니까?
  3. 취소 요청 이후 이미 실행된 외부 side effect는 어떻게 조정합니까?
