Day 11 · 빠른 참고

WAL과 체크포인트를 이용한 크래시 복구 설계

Day 9의 append-only 로그를 데이터 페이지 영속화 순서와 복구 시간으로 연결한다.

핵심 판단 기준

  • 데이터 페이지 영속화 전에 해당 WAL 영속화.
  • 성공 응답의 내구성 계약을 commit 설정과 연결.
  • 복구는 엔진의 redo 시작점·트랜잭션 가시성 규칙을 따른다.
  • WAL 삭제 전 복제·아카이브·백업 보존 조건 확인.
  • 복구 시간 ≈ 재생량/실측 속도 + 시작·검증 시간.

복습용 용어

WAL
데이터 페이지보다 먼저 영속화하는 변경 로그와 그 기록 규칙.
Redo
로그에 근거해 데이터 변경을 다시 적용하는 복구 작업.
Checkpoint
복구 시작 범위와 페이지 영속 상태를 정리하는 엔진의 복구 지점.

다시 확인

  • PostgreSQL WAL — 선행 로그 영속화와 redo·group commit의 원리.
  • PostgreSQL 체크포인트 — 복구 시간·I/O·WAL 보존의 trade-off.
