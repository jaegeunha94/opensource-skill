종합 설계 면접 — 주문 저장소의 인덱스와 로그 구조

저장 구조를 고르는 답은 이름을 말하는 데서 끝나지 않는다. 쓰기·읽기·삭제·복구의 비율을 먼저 수치화한다.

오늘의 학습 결과: B+Tree와 LSM 계열을 workload에 맞춰 비교하고 운영비용을 설명한다

면접 질문

초당 30,000건을 append하고 최근 주문은 키로 조회하며, 오래된 주문은 하루 단위 범위로 내보내는 저장소를 설계해 보세요.

실무 상황: 기록은 append 중심이며 수정과 삭제는 드물다. 주문번호 point read와 날짜 범위 export가 함께 있고, 복구 후 검색 가능해야 한다.

왜 묻는가: 파일 구조의 asymptotic cost뿐 아니라 block I/O, compaction, index 크기, crash recovery를 설명하는지 평가한다.

전제 개념

디스크는 메모리와 달리 페이지 단위로 읽고 쓴다. 랜덤 접근은 여러 페이지를 찾아야 하고, 순차 쓰기는 인접 블록을 묶어 효율을 낼 수 있다. 인덱스는 찾는 페이지 수를 줄이는 추가 파일이다.

B+Tree는 업데이트 즉시 탐색 구조를 유지해 point/range read에 강하고, LSM은 메모리 buffer에 모아 순차 쓰기를 늘리는 대신 compaction과 읽기 증폭을 관리한다. 어느 쪽도 모든 workload에서 이기지 않는다.

답변 사고 순서

  1. 워크로드: 초당 쓰기, point/range read, update/delete, 보존 기간과 p99 목표를 먼저 계산한다.
  2. 페이지 비용: 인덱스 fanout, 캐시 적중, random read IOPS, sequential bandwidth를 추정한다.
  3. 구조 선택: 낮은 읽기 지연이 핵심인지, 높은 append 처리량이 핵심인지 비교한다.
  4. 회복성: WAL, checksum, snapshot, compaction 중단 시 복구와 디스크 여유 공간을 포함한다.
  5. 운영 실험: 실제 데이터 크기·압축률로 쓰기/읽기 증폭과 공간 회수 시간을 측정한다.

케이스 풀이와 답변 예시

이 workload가 write-heavy여도 최근 주문 point lookup의 지연 SLO가 엄격하다면 LSM에서 Bloom filter와 block cache, compaction 정책을 검토해야 한다. B+Tree를 선택할 때도 랜덤 write와 페이지 split, WAL을 추적한다.

먼저 보존 기간까지 포함한 쓰기·읽기·범위 export 비율과 p99 목표를 확인하겠습니다. write가 압도적이고 point read가 캐시에 잘 맞는다면 LSM을 후보로 두고, compaction 자원과 temporary disk 여유, read amplification을 부하 테스트하겠습니다. 범위 scan 지연과 운영 단순성이 더 중요하거나 update가 잦으면 B+Tree 계열을 비교하겠습니다. 선택 이후에도 장애 복구 시간과 디스크 사용량을 합격 기준에 넣겠습니다.

답변에서 드러나는 점: 구조를 선호로 정하지 않고 I/O 모델과 SLO, 유지비용을 함께 계산한다.

Trade-off

선택얻는 점비용·위험
B+Treepoint/range read가 예측 가능하고 최신 키를 바로 찾기 쉽다.랜덤 페이지 쓰기, split, WAL과 cache 경쟁 비용이 든다.
LSMappend와 batch write가 효율적이고 sequential I/O를 활용한다.compaction으로 write/read/space amplification이 생기며 tail latency 조절이 필요하다.
파일 분할/날짜 partition오래된 데이터 제거와 기간 범위 export가 단순해진다.파티션 수, 경계 선택, 여러 파일 동시 탐색 비용이 증가한다.

흔한 오해

append-only와 LSM은 쓰기가 순차적이므로 디스크 비용이 사실상 없다.

memtable flush 뒤 compaction이 데이터를 다시 읽고 쓴다. 총 write amplification과 disk headroom, compaction이 foreground read에 주는 간섭을 측정해야 한다.

직접 풀어보기

쓰기 처리량은 목표의 두 배지만 compaction 중 p99 read가 8배 느려집니다. 어떤 데이터를 확인하고 어떤 완화안을 비교하겠습니까?

예시 풀이와 피드백 보기

compaction backlog, read/write amplification, block cache hit, I/O queue depth, compaction bandwidth와 disk headroom을 본다. compaction rate/priority, leveled-tiered 정책, shard 분리, 읽기 캐시와 과부하 backpressure를 비교한다.
