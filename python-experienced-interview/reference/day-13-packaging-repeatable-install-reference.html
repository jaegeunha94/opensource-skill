Day 13 · 빠른 참고

패키징과 의존성 관리 — 선언·잠금·설치 검증

Day 11 테스트·Day 12 진단을 배포 artifact와 설치 환경의 재현성으로 확장한다.

핵심 판단 기준

  • 선언=호환 범위, lock=선택한 해석 결과, hash=artifact 확인.
  • venv는 설치 공간 격리이며 버전 고정 도구가 아니다.
  • 빌드 wheel을 clean venv에 설치하고 저장소 밖에서 검증.
  • Python·OS·CPU·marker·wheel 지원을 비교.
  • 서비스 pin과 공개 라이브러리 지원 범위를 구별.

복습용 용어

Wheel
설치를 위해 빌드된 Python 배포 파일.
Build backend
배포 파일을 생성하는 빌드 도구 구현.
Editable install
개발 소스 변경을 설치 환경에서 바로 반영하는 설치 방식.
Lock
특정 조건에서 선택한 직접·간접 의존성 버전과 관련 정보를 기록한 결과.

다시 확인

  • PyPA pyproject.toml — 빌드 시스템과 프로젝트 metadata·의존성.
  • pip Repeatable Installs — 버전 고정·hash·wheel 보관의 보장 범위.
  • PyPA src와 flat layout — 로컬 소스 import와 설치 패키지 검증의 차이.
