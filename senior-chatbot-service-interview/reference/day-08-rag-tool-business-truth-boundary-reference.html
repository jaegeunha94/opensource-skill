Day 8 · 빠른 참고

RAG와 Tool Calling 연동 — 설명 근거와 업무 사실의 경계

정책 검색·현재 상태 조회·변경 실행을 나누고 사용자에게 확인된 사실만 전달한다.

핵심 판단 기준

  1. RAG는 정책 설명, 조회 tool은 현재 사실, 변경 tool은 부작용.
  2. 실행 인자는 제안; host가 schema·소유권·상태·정책·확인을 검증.
  3. 확인은 대상·금액·action에 바인딩.
  4. 조회 실패와 실행 결과 불명을 분리, 무조건 재실행 금지.
  5. 최종 응답은 근거와 확인된 업무 결과를 나눠 표현.

복습용 용어

grounding
답변의 주장을 확인 가능한 근거에 연결하는 것.
tool proposal
모델이 제안한 도구와 인자. 실행 인가가 아니다.
approval binding
확인을 특정 대상·인자·행동에 묶어 다른 실행에 재사용하지 않는 조건.
idempotency key
재요청이 동일 업무 효과를 중복 만들지 않도록 식별하는 key.
