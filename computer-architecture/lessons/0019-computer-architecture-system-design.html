컴퓨터 구조와 시스템 설계 — 저장 계층이 만드는 비용

DB 조회가 느릴 때 인덱스만 추가하면 해결될까? CPU, 캐시, 메모리, SSD 사이의 이동 비용을 읽기 패턴과 함께 판단한다.

오늘의 학습 결과: 작업 집합과 접근 패턴을 이용해 저장·캐시·인덱스 설계를 비교한다

면접 질문

초당 조회량이 늘면서 p99가 40ms에서 280ms로 뛰었습니다. 인덱스와 캐시를 어떻게 판단하겠습니까?

실무 상황: 주문 조회 API가 커진 뒤 p50은 거의 그대로인데 p99가 크게 악화됐다. DB CPU는 45%, 디스크 읽기 지연과 buffer cache miss가 증가했고, 데이터는 메모리보다 크다.

왜 묻는가: 복잡도 표만 읊지 않고 실제 하드웨어 경로를 가설로 세우고, 계측으로 검증하는지 본다.

전제 개념

CPU는 레지스터와 캐시에서 빠르게 값을 읽지만, DRAM은 더 느리고 SSD 접근은 훨씬 더 느리다. 데이터 구조의 크기와 접근 순서는 이 계층을 몇 번 왕복하는지를 바꾼다.

인덱스는 검색 범위를 줄이는 대신 저장 공간과 쓰기 작업을 늘린다. 캐시는 읽기 비용을 줄이는 대신 오래된 값, 무효화, 메모리 압박을 만든다. 먼저 병목이 CPU 연산인지, 메모리 miss인지, I/O인지 구분해야 한다.

답변 사고 순서

  1. 작업 집합: 핫한 주문·고객 데이터가 메모리에 들어가는지 추정하고 시간대별 분포를 확인한다.
  2. 경로 측정: 실행 계획, buffer hit/miss, 랜덤 I/O, p95/p99를 같은 요청 표본에서 연결한다.
  3. 접근 패턴: 무작위 point lookup인지 범위 순회인지, 키와 레코드가 얼마나 흩어져 있는지 본다.
  4. 후보 비교: 복합/covering index, 데이터 재배치, 애플리케이션 캐시를 읽기·쓰기·공간 비용으로 비교한다.
  5. 안전한 검증: 대표 트래픽으로 shadow 또는 canary를 실행하고 p99와 쓰기 지연, 캐시 hit ratio를 같이 본다.

케이스 풀이와 답변 예시

먼저 느린 쿼리의 실행 계획에서 인덱스 탐색 뒤 heap fetch가 반복되는지 확인한다. 실제 조회 열을 포함하는 인덱스가 도움이 될 수 있지만, 데이터 갱신이 잦으면 추가 인덱스의 쓰기 비용도 재야 한다.

현재 증거만으로 캐시를 먼저 넣지는 않겠습니다. 해당 요청의 실행 계획과 buffer hit, heap fetch를 확인해 랜덤 페이지 읽기가 원인인지 분리하고, 자주 함께 읽는 열에 대한 covering index를 제한된 표본에 적용하겠습니다. p99 개선과 WAL·인덱스 크기·쓰기 지연을 함께 비교한 뒤, 핫키 편중이나 오래된 값 허용 범위가 확인되면 캐시를 검토하겠습니다.

답변에서 드러나는 점: 하드웨어 용어를 나열하지 않고 DB 지표와 실제 데이터 이동 비용을 연결했다. 측정 후 작은 변경을 검증한다.

Trade-off

선택얻는 점비용·위험
Covering index테이블 페이지 접근을 줄여 읽기 tail latency를 낮출 수 있다.인덱스가 커지고 insert/update, vacuum, cache footprint 비용이 증가한다.
애플리케이션 캐시같은 키 반복 조회의 DB 왕복을 줄인다.무효화·staleness·핫키·메모리 압박을 운영해야 한다.
순차 배치 읽기페이지 지역성을 높이고 read amplification을 낮춘다.요청 지연과 메모리 버퍼 크기가 늘고, 임의 point read에는 부적합할 수 있다.

흔한 오해

인덱스가 있으면 조회는 항상 빨라진다.

인덱스가 선택되지 않거나 heap fetch가 여전히 많을 수 있고, 읽기 성능 이득이 쓰기·캐시 오염 비용보다 작은 경우도 있다. 실행 계획과 실제 분포를 확인한다.

직접 풀어보기

행 2억 개 테이블에서 특정 고객의 최신 20건을 읽는다. 현재는 customer_id 인덱스 탐색 뒤 정렬하고, 동시 쓰기도 많다. 어떤 인덱스 후보와 지표를 제안할지 말해 보세요.

예시 풀이와 피드백 보기

(customer_id, created_at DESC) 후보를 staging의 실제 분포로 비교한다. 조회가 필요한 열까지 포함할지는 인덱스 팽창과 업데이트 비용을 따져 정하며, p99·heap fetch·인덱스 크기·쓰기 지연을 함께 측정한다.
