접근성·사용성 가드레일을 포함한 UX 실험 설계

Day 19의 지표를 협업 회의에서 쓸 수 있는 출시 판단 문장으로 바꾼다. 통계 방법론보다 용어와 합의 기준에 집중한다.

레슨 목록 · 이전 Day 19 · 빠른 참고

협업 상황: 클릭이 늘었는데 출시해도 될까?

가상 결제 화면 B는 ‘다음’ 버튼 클릭률을 높였습니다. 그러나 키보드 사용자는 할인 상세 창에서 포커스를 밖으로 이동할 수 없습니다. PM은 클릭 증가를, 개발자는 오류율을, 디자이너는 완료 동선을 말합니다. 오늘의 목표는 각 신호를 같은 출시 판단에 묶는 용어를 사용하는 것입니다.

전제 용어를 정확히 쓰기

Primary metric(주지표)은 바꾸고 싶은 핵심 사용자 결과입니다. 이 화면에서는 버튼 클릭보다 ‘결제를 시작한 사용자 중 중복 청구 없이 주문을 완료한 비율’이 목표에 맞습니다. Guardrail metric(가드레일 지표)은 좋아지길 기대하는 지표와 별도로 악화시키면 안 되는 품질을 관측합니다. 오류·완료 시간·문의 증가가 후보입니다. Microsoft의 실험 지표 분류를 읽어 두 역할을 구별하세요.

Acceptance criterion(수용 기준)은 작업을 받아들일 구체적 조건입니다. ‘접근성이 좋다’ 대신 ‘키보드만으로 창을 열고 닫으며 원래 위치로 돌아가 결제를 끝낼 수 있다’라고 씁니다. Stop condition(중단 조건)은 실험 도중 심각한 문제가 나타나면 노출을 멈출 조건입니다.

키보드 trap 금지는 WCAG 2.2 §2.1.2의 기준입니다. 포커스가 창 안을 순환하는 modal 자체가 trap인 것은 아닙니다. 키보드로 닫아 빠져나갈 수 있는지가 핵심입니다. ‘평균 전환율이 올랐다’는 접근 불가능한 사용자의 문제를 상쇄하지 않습니다.

해석 순서와 피드백 문장

  1. 계측 품질을 확인합니다. 한 버전에서 완료 이벤트가 두 번 쌓였다면 클릭·완료 증가를 해석하기 전에 수정해야 합니다.
  2. 필수 접근 동선의 수용 기준을 통과했는지 확인합니다.
  3. 가드레일과 사용자군별 피해를 보고, 주지표 개선을 판단합니다.
  4. 결정·담당자·재검증 조건을 한 문장으로 기록합니다.
“B는 완료 지표가 좋아졌지만 키보드로 상세 창을 닫지 못해 수용 기준을 통과하지 못했습니다. B 노출을 중단하고 포커스 복귀를 수정한 뒤, 동일 결제 동선과 완료 계측을 재검증하겠습니다.”

많은 지표는 피해를 발견하기 좋지만 출시 판단이 흐려질 수 있으므로 역할과 우선순위를 먼저 정합니다. 전체 평균은 읽기 쉽지만 작은 사용자군의 큰 피해를 숨길 수 있습니다. 세그먼트 비교는 이를 찾지만 표본이 작다는 이유로 무조건 안전이나 실패를 단정하지 않습니다.

직접 고쳐 쓰기

다음 리뷰를 고쳐 보세요. “전환이 올랐으니 접근성 이슈는 출시 후 처리. 오류율이 같으므로 문제 없음.” 어떤 용어와 근거가 빠졌습니까?

예시와 피드백

“주지표 분모와 완료 계측부터 확인하고, 키보드 결제 동선의 수용 기준·사용자군별 완료율을 검증하겠습니다. 접근이 막히면 중단 조건에 따라 B 노출을 멈춥니다.” 전체 오류율은 키보드로 버튼 자체에 도달하지 못해 오류 이벤트조차 안 찍힌 사용자를 놓칠 수 있습니다. ‘접근성 점수 100’만 요구하는 답은 실제 동선의 수동 검증을 빠뜨립니다.
