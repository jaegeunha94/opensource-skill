Transactional Outbox와 멱등 이벤트 처리

Day 5 트랜잭션·Day 7 재시도·Day 12 신뢰성에 기반해 주문 저장과 이벤트 발행 사이의 유실 구간을 없앤다.

핵심 판단 기준

  • 주문+outbox는 같은 DB commit.
  • relay 전송 확인 후 sent 표시. 그 사이 crash의 중복은 정상 복구 경로.
  • 소비자 inbox unique+업무 변경은 같은 commit, ack는 이후.
  • 외부 부작용은 별도 멱등 계약; 주문별 순서는 별도 sequence.
  • oldest unsent age·발행 실패·중복 적용·재처리 결과로 검증.

복습용 용어

Outbox
업무 데이터와 같은 트랜잭션에서 저장하는 발행 대기 이벤트.
Relay
outbox 이벤트를 broker에 전달하고 발행 상태를 기록하는 처리기.
Inbox
소비자가 적용한 이벤트 ID를 저장해 중복 적용을 막는 기록.

다시 확인

  • Chris Richardson, Transactional Outbox — DB·발행 경계와 relay 중복의 원 패턴 설명.
  • SQLAlchemy 2.0 session transaction — 기존 과목의 2.0 예제에서 commit·rollback 범위 확인.
