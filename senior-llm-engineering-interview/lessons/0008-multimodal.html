Multimodal 입출력 — 품질·지연·비용을 modality별로 나누기

이미지나 오디오를 텍스트처럼 한 번에 전달한다고 가정하면 크기·비용·프라이버시와 실패 조건을 놓친다.

오늘의 학습 결과: modality별 전처리·평가·fallback 경계를 설계한다

면접 질문

사용자가 영수증 사진과 음성 설명을 함께 제출하는 경비 심사 시스템을 어떻게 설계하겠습니까?

실무 상황: 영수증은 흐릿하거나 여러 장일 수 있고, 음성에는 개인 정보가 포함된다. 모델 추출 결과는 금액·계정 정산에 사용된다.

왜 묻는가: 모델 capability보다 입력 전처리·출처·불확실성·사람 확인과 운영 비용을 설계하는지 본다.

전제 개념

multimodal 모델은 이미지·오디오 같은 입력을 받아 언어 출력을 만들 수 있다. 서비스는 파일 검증, 크기 제한, 변환, 모델 호출, 결과 검증을 거쳐야 하며 각 단계가 실패할 수 있다.

모델이 숫자를 읽었다고 원본과 일치하는 것은 아니다. OCR/vision 결과를 구조화하고 금액 합계·통화·영수증 필드의 schema와 confidence/증거를 검증한다.

답변 사고 순서

  1. 입력 계약: 파일 타입·크기·장수·오디오 길이와 언어, 사용자 동의/보존 정책을 정한다.
  2. 전처리: 이미지 회전·해상도·crop과 오디오 transcription이 필요한지 품질·비용으로 비교한다.
  3. 모델 경로: 영수증 이미지와 음성을 직접 함께 넣거나 별도 추출 후 합치는 방식을 평가한다.
  4. 결과 검증: 금액·세금·통화 합계와 원본 근거를 대조하고 불확실한 필드는 사용자 확인을 요구한다.
  5. 운영 설계: latency·token/image 비용·재시도·PII logging·삭제 요청과 fallback을 관찰한다.

케이스 풀이와 답변 예시

영수증 금액이 모델에서 8,900원으로 추출됐지만 총액 필드가 89,000원으로 읽히면 자동 승인하지 않는다. 원본 crop, 추출 필드와 검증 규칙을 보여주고 사용자가 확인하게 한다.

원본 파일을 안전하게 검증하고 최소 해상도·장수·오디오 길이를 제한하겠습니다. 초기에는 이미지와 음성을 각각 구조화 추출해 provenance를 남기고, 합계·통화·세금 규칙을 deterministic validator로 확인하겠습니다. 불일치나 낮은 품질은 사용자 재촬영 또는 사람 승인으로 넘기고, 파일은 동의된 보존 기간 후 삭제하겠습니다. 정확도와 함께 p95, 입력 크기당 비용, rejection·manual review rate를 측정하겠습니다.

답변에서 드러나는 점: 불확실한 모델 출력이 금전 결정으로 직접 이어지지 않도록 deterministic 검증을 둔다.

Trade-off

선택얻는 점비용·위험
원본 multimodal 직접 처리텍스트·시각 맥락을 함께 판단할 수 있다.입력 비용, latency, provenance 추적과 재현성 제어가 필요하다.
OCR/ASR 전처리 후 LLM단계별 점검·재처리와 field validator가 쉽다.전처리 오류가 누적되고 원본의 공간·음향 맥락이 손실될 수 있다.
자동 승인 범위 확대빠른 사용자 경험과 낮은 review 비용을 얻는다.고액·저품질 입력에서 오분류와 재무 피해 위험이 커진다.

흔한 오해

모델이 멀티모달 입력을 이해하므로 OCR/ASR과 입력 검증은 필요 없다.

모델은 확률적 추출을 수행한다. 입력 품질·필드 단위 오류·정합성 검사를 서비스가 책임져야 한다.

직접 풀어보기

같은 영수증을 두 번 넣었더니 금액이 다르게 추출됩니다. 자동화율을 유지하면서 위험을 줄이는 정책을 정해 보세요.

예시 풀이와 피드백 보기

필수 필드와 합계 validator가 통과하고 금액이 허용된 신뢰 기준을 만족할 때만 자동 경로를 사용한다. 불일치 sample은 재시도 대신 사용자 확인/수동 검토로 보내고 model/version별 품질을 측정한다.

자가 피드백: end-to-end 품질을 모델 정확도 하나로 축약하지 않았는가?

  2. image resizing이 글자 인식률과 token cost에 미치는 영향을 어떻게 평가하나요?
  3. 모델 제공자가 파일 데이터를 보존하는지 어떻게 검증하고 사용자에게 알립니까?
