Multimodal 입출력 — 품질·지연·비용을 modality별로 나누기

modality별 전처리·평가·fallback 경계를 설계한다

핵심 판단

이미지나 오디오를 텍스트처럼 한 번에 전달한다고 가정하면 크기·비용·프라이버시와 실패 조건을 놓친다.

multimodal 모델은 이미지·오디오 같은 입력을 받아 언어 출력을 만들 수 있다. 서비스는 파일 검증, 크기 제한, 변환, 모델 호출, 결과 검증을 거쳐야 하며 각 단계가 실패할 수 있다.

검토 순서

  1. 입력 계약: 파일 타입·크기·장수·오디오 길이와 언어, 사용자 동의/보존 정책을 정한다.
  2. 전처리: 이미지 회전·해상도·crop과 오디오 transcription이 필요한지 품질·비용으로 비교한다.
  3. 모델 경로: 영수증 이미지와 음성을 직접 함께 넣거나 별도 추출 후 합치는 방식을 평가한다.
  4. 결과 검증: 금액·세금·통화 합계와 원본 근거를 대조하고 불확실한 필드는 사용자 확인을 요구한다.
  5. 운영 설계: latency·token/image 비용·재시도·PII logging·삭제 요청과 fallback을 관찰한다.

선택 비교

선택얻는 점비용·위험
원본 multimodal 직접 처리텍스트·시각 맥락을 함께 판단할 수 있다.입력 비용, latency, provenance 추적과 재현성 제어가 필요하다.
OCR/ASR 전처리 후 LLM단계별 점검·재처리와 field validator가 쉽다.전처리 오류가 누적되고 원본의 공간·음향 맥락이 손실될 수 있다.
자동 승인 범위 확대빠른 사용자 경험과 낮은 review 비용을 얻는다.고액·저품질 입력에서 오분류와 재무 피해 위험이 커진다.

주의할 함정

오해: 모델이 멀티모달 입력을 이해하므로 OCR/ASR과 입력 검증은 필요 없다.

실제 경계: 모델은 확률적 추출을 수행한다. 입력 품질·필드 단위 오류·정합성 검사를 서비스가 책임져야 한다.

면접에서 꺼낼 사례

영수증 금액이 모델에서 8,900원으로 추출됐지만 총액 필드가 89,000원으로 읽히면 자동 승인하지 않는다. 원본 crop, 추출 필드와 검증 규칙을 보여주고 사용자가 확인하게 한다.

확인 질문: 같은 영수증을 두 번 넣었더니 금액이 다르게 추출됩니다. 자동화율을 유지하면서 위험을 줄이는 정책을 정해 보세요.
