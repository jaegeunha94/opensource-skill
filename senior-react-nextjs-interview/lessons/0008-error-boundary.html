Error Boundary — UI 실패를 격리하고 복구 행동 제공하기

Error Boundary는 모든 JavaScript 오류를 잡는 전역 try/catch가 아니다. render tree의 실패 범위와 서버·비동기 오류 경계를 구분한다.

오늘의 학습 결과: boundary 위치와 fallback·reset·관측을 제품 단위로 설계한다

면접 질문

대시보드 차트 하나가 render 중 throw할 때 전체 화면 대신 해당 영역만 복구하려면 어떻게 하겠습니까?

실무 상황: 페이지에는 navigation, 결제 요약, 추천 차트와 고객 테이블이 있다. 차트 library가 일부 데이터에서 렌더 오류를 내며 사용자는 다른 기능을 계속 써야 한다.

왜 묻는가: boundary가 잡는 오류 범위와 못 잡는 오류를 알고 사용자 업무 단위로 격리하는지 본다.

전제 개념

Error Boundary는 자식 component의 rendering/lifecycle 오류를 감지해 fallback UI를 보여주는 React 경계다. fallback을 어디에 둘지는 실패한 기능 때문에 사용자가 잃는 업무 범위로 정한다.

event handler, 일반 비동기 callback, SSR 오류는 client Error Boundary가 모두 잡아주지 않는다. API 요청 실패는 query/data layer의 error state와 Next.js route-level error UI를 별도로 설계해야 한다.

답변 사고 순서

  1. 오류 종류: render exception, event handler, data fetch, server render를 구분한다.
  2. 경계 배치: 차트/위젯별 격리와 페이지 전체 fallback 중 사용자 작업 유지 범위를 정한다.
  3. 복구 설계: retry/reset 조건, 재요청, stale data 표시와 문제 신고 경로를 만든다.
  4. 관측 연결: component stack, route, release, correlation id를 수집하되 개인정보를 제거한다.
  5. 반복 방지: 오류 loop·무한 retry·fallback 내부 오류와 접근성 focus 이동을 검증한다.

케이스 풀이와 답변 예시

차트 실패가 내비게이션과 청구 요약까지 막아서는 안 된다. 독립 widget boundary를 둬 오류 메시지와 다시 불러오기 버튼을 보여주고, 원인이 영구적인 schema 오류면 무한 재시도하지 않는다.

우선 실패가 React render 오류인지 API 요청 오류인지 분리하겠습니다. 독립적인 차트 위젯에 boundary를 두어 다른 업무는 유지하고, fallback은 마지막 정상 데이터를 보여줄지와 retry 가능 여부를 명시하겠습니다. reset 때 query cache나 오류 상태도 함께 초기화하고, component stack·release·route를 수집해 재현 가능한 관측성을 확보하겠습니다. event handler와 server rendering 오류는 별도 error handling 경로를 두겠습니다.

답변에서 드러나는 점: 컴포넌트 트리 보호뿐 아니라 데이터 오류·서버 오류·사용자 복구를 구분한다.

Trade-off

선택얻는 점비용·위험
페이지 단위 boundary구현과 오류 집계가 단순하다.한 widget 오류가 페이지 전체 경험을 대체할 수 있다.
widget 단위 boundary실패 반경을 줄이고 다른 작업을 유지한다.fallback·retry·telemetry를 각 기능에 일관되게 설계해야 한다.
마지막 정상 데이터 유지일시 장애에도 읽기 경험을 지킨다.stale 표시 없이 보여주면 잘못된 정보로 오인될 수 있다.

흔한 오해

Error Boundary가 있으면 모든 예외를 잡아 앱이 crash하지 않는다.

Boundary는 주로 하위 render/lifecycle 오류를 포착한다. event handler, 임의 async callback, server-side rendering 오류는 별도 경로로 처리한다.

직접 풀어보기

사용자가 버튼을 눌러 fetch했는데 Promise rejection이 발생했습니다. Error Boundary만 추가하면 처리될까요?

예시 풀이와 피드백 보기

일반 event handler/비동기 rejection은 자동 포착되지 않는다. query state나 try/catch에서 오류 상태를 처리하거나 명시적으로 render 단계로 전달하고, 사용자 재시도와 관측을 추가한다.
