Day 9 · 빠른 참고

Hydration 심화 — 서버와 첫 클라이언트 렌더를 맞추기

Day 8의 실패 격리에 더해, 서버 HTML과 첫 렌더의 불일치 원인을 재현하고 제거한다.

핵심 판단 기준

  • 첫 렌더는 서버와 같은 데이터·포맷·DOM 구조.
  • 브라우저 선호는 공통 초기값 이후 정상 업데이트.
  • use client ≠ 서버 사전 렌더 제외.
  • suppressHydrationWarning은 한 단계 탈출구이며 값 복구가 아니다.

복습용 용어

Hydration
서버 HTML을 클라이언트 React 트리와 연결해 상호작용을 활성화하는 과정.
Deterministic first render
같은 초기 입력에서 서버와 브라우저가 같은 첫 화면을 만드는 렌더.
Two-pass rendering
같은 초기 화면을 먼저 렌더한 뒤 클라이언트 상태를 반영하는 두 단계 방식.

다시 확인

  • React hydrateRoot — 초기 일치 계약과 warning 억제의 제한.
  • Next.js hydration 오류 — 잘못된 중첩·브라우저 입력 등 원인과 완화.
  • React useEffect — 서버·클라이언트의 effect 실행 차이.
