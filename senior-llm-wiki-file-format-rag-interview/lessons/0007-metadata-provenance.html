Metadata와 Provenance — 답변 근거를 원본까지 추적하기

답변에 문서 제목 하나를 표시하는 것으로는 근거를 재현하기 어렵다. 원본 버전과 변환 과정이 연결돼야 한다.

오늘의 학습 결과: 각 chunk의 출처·버전·위치·변환 기록을 모델 출력까지 보존한다

면접 질문

PDF에서 추출한 표를 근거로 답변할 때 원문이 개정되거나 parser가 바뀌어도 인용을 검증하려면 어떤 metadata를 저장합니까?

실무 상황: 정책 문서는 여러 저장소에서 오고, PDF·HTML·스캔 문서가 섞여 있다. OCR/parser가 바뀌면 chunk 경계와 인용 페이지가 달라질 수 있다.

왜 묻는가: metadata를 검색 filter의 보조값으로만 보지 않고 lineage·권한·재현성·삭제의 기반으로 보는지 평가한다.

전제 개념

provenance는 데이터가 어디서 왔고 어떤 변환을 거쳐 현재 값이 되었는지 기록하는 것이다. RAG에서는 답변 문장 → retrieved chunk → parsed artifact → 원본 파일의 연결을 보존한다.

파일 경로는 원본 identity를 보장하지 않고 같은 경로의 내용은 바뀔 수 있다. content hash와 source version, ingestion run id를 함께 저장해야 이전 답변을 재현할 수 있다.

답변 사고 순서

  1. 원본 identity: source system, stable document id, version/ETag, content hash, ACL snapshot을 기록한다.
  2. 변환 lineage: parser/OCR/model 버전, 설정, 실행 id, 오류와 page/section/table 위치를 기록한다.
  3. chunk identity: chunk id를 source version·transform version·location에 연결한다.
  4. 답변 추적: 응답에서 사용한 chunk id와 검색 score/filter, prompt/model version을 저장한다.
  5. 변경·삭제: 새 버전 색인과 기존 버전 폐기, 권한 변경·삭제 전파를 검증한다.

케이스 풀이와 답변 예시

사용자가 “정책 4.2절” 인용을 누르면 현재 파일의 같은 page가 아니라 답변을 만들 당시 source version과 section으로 연결돼야 한다. 원본이 갱신됐으면 이전 인용을 과거 버전 표시 또는 최신 문서로 유도한다.

문서 경로와 파일명만 저장하지 않고 원본 시스템의 stable id, version/ETag, hash를 보존하겠습니다. 각 ingestion run에는 parser/OCR 버전과 설정을 기록하고 chunk는 원본 버전과 page·section·table cell에 연결하겠습니다. 답변에는 사용한 chunk id와 retrieval 조건을 기록해 재현 가능하게 하고, ACL 변경과 삭제 요청이 vector store·cache·answer trace까지 전파되는지 검증하겠습니다.

답변에서 드러나는 점: citation 품질을 검색 결과의 제목이 아니라 데이터 lineage의 완전성으로 설명한다.

Trade-off

선택얻는 점비용·위험
간단한 source URL만 기록저장 공간과 구현이 작다.같은 URL의 수정 이후 답변을 재현하지 못하고 권한 변경 추적이 어렵다.
불변 source version + 변환 manifest답변 재현과 parser 변경 비교, 감사가 가능하다.저장 비용과 version lifecycle·삭제 정책이 필요하다.
원문 전체 복제검색과 장애 복구에서 독립성이 커진다.저작권·개인정보·ACL drift와 중복 저장을 관리해야 한다.

흔한 오해

문서 제목과 페이지 번호를 인용하면 답변을 검증할 수 있다.

문서가 수정되거나 parser가 페이지를 다르게 나눌 수 있다. 답변 당시의 version과 추출 위치, 변환 run을 함께 보존한다.

직접 풀어보기

검색 결과에는 정확한 문서 제목이 있지만 source version hash가 없습니다. 감사 질문에 답할 수 없는 지점을 설명하고 최소 metadata를 제안하세요.

예시 풀이와 피드백 보기

어느 시점의 원문이 검색·인용됐는지 증명할 수 없다. source stable id, version/ETag 또는 hash, ingestion run id, parser version, chunk location을 추가한다.

자가 피드백: 답변을 당시 입력에서 재현할 수 있는가? 삭제·ACL 변경도 추적되는가?
