면접 질문·실무 상황

당신이 떠난 뒤 새 팀이 outbox 설계를 지우려 합니다. 당시 결정을 어떻게 남겨야 재검토가 가능할까요?

Day 12의 결제 팀은 피크 전 전면 전환 대신 점진 outbox를 선택했습니다. 운영팀은 소비 지연을 우려했습니다. 면접관은 문서 작성량보다 당시 제약·반대 근거·결정 권한·후속 검증을 연결하는지 봅니다.

전제 개념

설계 제안서가 여러 선택을 토론하는 문서라면 ADR은 중요한 선택 하나와 그 이유·결과를 보존하는 기록입니다. ‘현재 우리는 무엇을 하며, 어떤 조건 때문에 그렇게 하는가’를 미래 동료에게 알려 줍니다. Michael Nygard의 원 글은 결정이 바뀌면 옛 기록을 지우지 않고 대체 기록과 연결하는 방식을 설명합니다.

합의는 전원 찬성과 다릅니다. 의견 수렴을 했는지, 미해결 위험을 누가 소유하는지, 정해진 권한으로 언제 결정했는지를 명시해야 합니다. ADR에 accepted라고 적는 것만으로 실제 승인이 생기지 않습니다.

답변 사고 순서와 완성된 가상 ADR

  1. 결정 범위를 하나로 줄입니다. ‘결제 시스템 전부 개편’ 대신 ‘피크 전 이벤트 저장에 outbox 도입’을 기록합니다.
  2. 측정된 사실과 가정을 구별합니다. 가정은 실험 결과로 갱신할 수 있게 만듭니다.
  3. 대안의 비용을 같은 축으로 비교하고 반대 의견의 실제 위험을 남깁니다.
  4. 결정권자·검토 참여자·실행 담당자와 검증 기준을 명시합니다.
  5. 조건 변화 때 새 ADR로 대체하고 이전 링크를 유지합니다.
가상 ADR-013 — 정산 이벤트를 DB outbox로 저장한다
상태: 제안됨. 결제·운영 책임자의 검토 후 수용 여부 결정.
맥락: 주문 commit 뒤 발행 실패 구간이 있으며, 피크까지 2주다. 소비 지연 목표는 5분 이내다.
결정: 주문과 이벤트를 같은 DB 트랜잭션으로 저장하고 relay·멱등 consumer를 점진 도입한다.
대안: 현행 재시도 보강은 구현이 작지만 commit 뒤 crash 유실 구간이 남는다. 전면 비동기 전환은 경계 통일에 좋지만 3팀의 피크 전 회귀 범위가 크다.
결과: 유실 복구 경로를 갖지만 outbox backlog·중복·보존 비용이 추가된다.
검증: crash 주입에서 성공 주문의 이벤트 누락 0, 중복 업무 적용 0, 피크 부하의 oldest unsent age 5분 미만.
담당·재검토: 가상 결제 담당은 relay, 운영 담당은 경보·복구 훈련을 맡는다. 5분 초과나 DB p99 회귀가 지속되면 확대를 멈추고 검토한다.

숫자는 이 레슨의 가상 계약입니다. 실제 기록에서는 근거 실험과 관측 기간을 연결해야 합니다.

강한 답변·Trade-off·오해

왜 outbox를 택했는지 피크 일정과 이벤트 손실 위험으로 설명하고, 현행 보강·전면 전환을 같은 비용 축에서 비교하겠습니다. 운영팀의 소비 지연 우려를 삭제하지 않고 기준·담당자로 바꿉니다. 조건이 바뀌면 이전 ADR을 superseded로 표시하고 새 결정에 연결하겠습니다.

약한 답변: ‘팀원이 동의할 때까지 설득합니다.’ 일정·책임·중단 기준이 빠져 결정이 끝나지 않습니다. 짧은 ADR은 읽기 쉽지만 구현 세부를 링크로 보완해야 합니다. 상세 문서는 검증 근거가 많지만 갱신 비용이 커집니다. 빠른 결정은 일정을 지키지만 검증되지 않은 가정을 만들므로 가역적 범위와 후속 검토를 명시합니다.

오해: accepted 결정은 다시 바꾸면 안 된다. 사실과 제약이 바뀌면 재검토하되 왜 바꿨는지 이력으로 남깁니다. AWS ADR 절차도 수명주기 관점으로 읽으세요.

연습·피드백

피크 실험에서 누락은 0이지만 소비 지연이 20분입니다. ADR의 어느 부분을 근거로 확대 결정을 내립니까?

예시 판단

합의한 5분 검증 기준을 넘었으므로 확대를 멈춥니다. relay 처리량·DB 부하·consumer 병목을 나누고 담당자와 재실험 조건을 기록합니다. ‘누락이 0이면 성공’은 운영 요구를 삭제하고, ‘outbox 폐기’는 저장 계약과 소비 병목을 같은 원인으로 단정합니다.

Follow-up·자기 점검

긴급 장애라 사전 합의가 어렵다면? incident commander의 임시 결정·만료 조건·영향을 기록하고 복구 후 정식 검토합니다.

새 팀이 관리형 이벤트 서비스로 옮긴다면? 예전 제약과 새 비용·보장·운영 역량을 비교해 새 ADR을 만듭니다. 제품 이름만 바꾸고 과거 가정을 재사용하지 않습니다.
