Day 9 · 빠른 참고

Replay와 평가 루프 — 실행 성공과 업무 정답의 분리

원본 trajectory를 보존하고, 부작용을 통제한 재실행에서 업무 결과와 행동을 함께 평가한다.

핵심 판단 기준

  • 완료 ≠ 정답. 최종 결과·금지 행동·실행 실패를 별도 측정한다.
  • Offline fixture는 부작용을 없애되 금지 도구 호출 시도를 기록한다.
  • 모델·시각·도구·메모리·Skill 버전을 함께 식별한다.
  • 원본을 보존하고 압축본에 생성 규칙·버전을 연결한다.

복습용 용어

Trajectory
대화와 도구 행동을 담은 실행 기록.
Fixture replay
고정된 도구 응답을 사용해 비교하는 평가 실행.
Rerun
정의한 환경에서 실제 agent 작업을 다시 실행하는 것.
Provenance
파생 데이터가 어느 원본과 변환에서 나왔는지의 추적 정보.

다시 확인

  • Hermes batch processing — 다중 작업 실행과 결과 수집
  • Hermes trajectory format — 정규화된 대화·도구 기록과 메타데이터
  • Hermes releases — batch·기록 형식의 버전 변화
