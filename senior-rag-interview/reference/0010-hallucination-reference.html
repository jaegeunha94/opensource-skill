RAG hallucination — 근거 부족을 감지하고 답을 제한하기

faithfulness·coverage·abstention을 업무 위험에 맞게 운영한다

핵심 판단

검색 문서가 있다는 사실은 답변의 근거가 충분하다는 뜻이 아니다. 검색 품질·생성 충실도·거절 기준을 따로 측정한다.

hallucination은 모델의 문장이 제공된 증거나 사실과 맞지 않는 경우다. RAG에서는 근거 문서를 찾지 못한 오류와 근거를 찾았지만 모델이 왜곡한 오류가 다르다.

검토 순서

  1. 오류 분류: 검색 실패, 오래된/권한 없는 문서, context 누락, 생성 왜곡, citation mismatch를 라벨링한다.
  2. 근거 계약: 각 핵심 claim에 supporting passage와 source version이 있는지 확인한다.
  3. 검색 평가: recall@k·MRR, freshness·ACL filter와 query rewrite 실패를 본다.
  4. 생성 평가: claim-level faithfulness, citation correctness, abstention precision을 사람 표본으로 검증한다.
  5. 배포 제어: 고위험 질문은 근거 부족 시 거절/상담으로 보내고 offline·online 지표를 함께 본다.

선택 비교

선택얻는 점비용·위험
엄격한 근거 기반 답변근거 없는 주장을 줄이고 감사 가능성을 높인다.자료가 불완전하면 답변 거절과 사용자 불편이 늘어난다.
넓은 context/retrieval관련 정보 누락 가능성을 낮출 수 있다.noise·상충 문서·token 비용이 커지고 모델이 중요한 근거를 놓칠 수 있다.
LLM judge 자동평가대량 regression을 빠르게 비교한다.judge 편향과 자기 선호가 있어 사람 검증과 gold evidence가 필요하다.

주의할 함정

오해: RAG에 citation을 붙이면 hallucination은 사라진다.

실제 경계: citation이 있어도 문장이 그 근거에서 지지되지 않을 수 있다. claim-to-passage entailment와 citation correctness를 평가해야 한다.

면접에서 꺼낼 사례

최신 정책 3.2절이 검색 top-5에 없고 폐기된 2.8절만 있다면 generation prompt는 hallucination의 유일 원인이 아니다. metadata freshness와 retrieval filter부터 고친다.

확인 질문: 검색 top-3는 올바른 최신 문서지만 답변이 단위와 숫자를 바꿨습니다. 어느 평가 계층과 검증으로 잡을까요?
