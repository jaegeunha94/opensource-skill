RAG 평가 — 데이터셋·지표·배포 판단의 연결

검색과 생성의 오류를 고정된 평가셋에서 분리하고 온라인 위험과 연결한다.

면접 질문과 실무 상황

Day 10에서 근거 부족과 왜곡을 분리했습니다. 새 retriever의 Recall@5는 올랐고 faithfulness는 0.94입니다. 바로 전 사용자에게 배포해도 됩니까?

면접관은 지표 이름보다 분모·데이터 누출·채점자 편향·위험군별 결과와 release gate를 설명하는지 봅니다.

전제 개념과 작은 계산

Recall@k는 정답 관련 문서/단위 중 top-k에 들어온 비율입니다. gold 관련 chunk가 A/B/C이고 top-5가 A/B/X/Y/Z라면 2/3입니다. gold를 문서로 만들었는지 chunk로 만들었는지에 따라 값이 달라집니다. chunking을 바꾸면 안정적인 근거 단위로 대응시키거나 새 gold를 만들어야 합니다.

faithfulness는 생성된 주장 중 제공 context가 뒷받침하는 비율을 보는 지표입니다. 답이 질문에 필요한 모든 조건을 담았는지, 그 문서가 최신·권한 있는지와는 다릅니다. 최신 규정 대신 폐기 규정에 충실한 답도 있을 수 있습니다. Ragas의 claim 기반 Context Recall과 ID 기반 retrieval Recall은 분모가 달라 동일한 숫자로 섞지 않습니다.

답변 사고 순서

  1. 정답 가능한 질문·답 없는 질문·시점 충돌·다국어·권한 제한·고위험 업무를 분리해 dataset을 만든다.
  2. 문서 snapshot·질문·gold passage/claims·권한·채점 규칙과 버전을 고정한다.
  3. 개선용 dev와 최종 holdout을 나누고 holdout에 맞춰 반복 튜닝하지 않는다.
  4. 동일 질문에 baseline/new를 실행해 검색 recall, 근거 사용, 정확성·완전성·거절을 분리한다.
  5. 자동 judge를 사람 표본과 비교해 불일치·채점 불안정을 확인한다. prompt/model/version도 고정한다.
  6. 오프라인 gate 통과 뒤 제한된 온라인 노출에서 사용자 교정·상담 전환·지연·비용을 본다.

구체적 배포 판단

가상 평가baseline → new판단
일반 질문 Recall@50.75 → 0.84검색 후보 개선
근거 있는 답의 faithfulness0.92 → 0.94생성 충실도 소폭 개선
답 없는 질문의 부당 답변3/100 → 12/100거절 위험 악화
권한 제한 자료 노출0/200 → 1/200보안 gate 실패; 평균 점수로 상쇄 불가

이 숫자는 학습용 가상 결과입니다. 온라인 A/B는 user/tenant 단위로 안정적으로 배정하고 평가 대상·기간·중단 기준을 미리 정합니다. 만족도 설문만으로 고위험 오답을 판단하지 않습니다. 표본이 작은 위험군의 0건도 위험이 없다는 증명은 아닙니다.

답변 예시와 trade-off

Recall 개선은 확인하되 답 없는 질문과 권한 제한군을 별도 gate로 보겠습니다. 같은 document snapshot과 holdout에서 검색 gold와 claim 정확성·거절을 분리하고, judge는 사람 검토로 보정하겠습니다. 이 예시는 부당 답변과 노출이 악화되어 전면 배포하지 않겠습니다. 원인을 고친 뒤 제한 노출에서 교정·상담·지연·비용을 함께 확인하겠습니다.

약한 답 “RAGAS 점수가 0.9 이상이면 배포합니다”는 지표 정의·표본·제품 위험을 생략합니다.

  • 사람 채점은 업무 해석에 강하지만 비용·일관성 문제가 있습니다. 자동 judge는 반복 규모가 크지만 모델 편향과 prompt 민감성이 있습니다.
  • 넓은 gold dataset은 대표성이 높지만 유지 비용이 큽니다. 고정 회귀셋과 최근 실패/분포 변화 표본을 함께 관리합니다.
  • 온라인 검증은 실제 유용성을 보지만 위험한 오답을 고객에게 보일 수 있습니다. 사전 gate·낮은 범위·중단 조건을 둡니다.

흔한 오해와 현재 API 확인

faithfulness 1.0은 사실 정확성·완전성 1.0이 아닙니다. Ragas 현재 문서는 collections 기반 API와 legacy 패턴을 구분합니다. 이 레슨은 특정 과거 import를 그대로 복사하지 않고 dataset·분모·채점 계약을 설명합니다. 도구 버전과 judge 조건은 평가 결과에 남겨야 재현할 수 있습니다.

연습과 피드백

답변 “환불 가능합니다”는 context의 한 문장에 충실합니다. 실제 정책에는 “구매 7일 이내·미개봉” 조건이 있고 질문은 30일 뒤 개봉 상품입니다. faithfulness만 보면 무엇을 놓치나요?

해설 보기

조건 누락과 질문에 대한 최종 정확성을 놓칩니다. 검색이 조건 문단을 가져왔는지, context에 포함됐는지, 답이 그 조건을 적용했는지 단계별로 봅니다. 근거 문장이 있다는 이유로 답을 합격시키지 않는 것이 핵심입니다.

Follow-up과 자기 점검

chunk 수를 늘려 recall을 올리면? noise·context 비용·생성 오류와 함께 측정합니다. 검색 recall만 최적화하지 않습니다.

judge 모델이 바뀌면? 같은 anchor 답안을 다시 채점해 척도 변화를 확인하고 이전 점수와 직접 비교할 수 있는 범위를 명시합니다.
