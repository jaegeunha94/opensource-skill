senior-rag-interview · Day 10 · 수동 학습 레슨

RAG hallucination — 근거 부족을 감지하고 답을 제한하기

검색 문서가 있다는 사실은 답변의 근거가 충분하다는 뜻이 아니다. 검색 품질·생성 충실도·거절 기준을 따로 측정한다.

오늘의 학습 결과: faithfulness·coverage·abstention을 업무 위험에 맞게 운영한다

면접 질문

내부 정책 RAG가 근거와 다른 답변을 내놓는 사례가 있습니다. 원인을 어떻게 분해하고 개선 효과를 평가하겠습니까?

실무 상황: 문서는 최신본과 폐기본이 함께 검색되고, 모델이 근거에 없는 조건을 자연스럽게 보완한다. 일부 질문은 정책 자체에 답이 없다.

왜 묻는가: 프롬프트만 바꾸지 않고 retrieval·context·generation·evaluation을 나눠 측정하는지 본다.

전제 개념

hallucination은 모델의 문장이 제공된 증거나 사실과 맞지 않는 경우다. RAG에서는 근거 문서를 찾지 못한 오류와 근거를 찾았지만 모델이 왜곡한 오류가 다르다.

답변을 무조건 거절하면 유용성이 낮아지고, 낮은 검색 score만으로 근거 부족을 판단하면 relevance 문제를 놓칠 수 있다. 도메인별 false answer와 false abstention 비용을 정의한다.

답변 사고 순서

  1. 오류 분류: 검색 실패, 오래된/권한 없는 문서, context 누락, 생성 왜곡, citation mismatch를 라벨링한다.
  2. 근거 계약: 각 핵심 claim에 supporting passage와 source version이 있는지 확인한다.
  3. 검색 평가: recall@k·MRR, freshness·ACL filter와 query rewrite 실패를 본다.
  4. 생성 평가: claim-level faithfulness, citation correctness, abstention precision을 사람 표본으로 검증한다.
  5. 배포 제어: 고위험 질문은 근거 부족 시 거절/상담으로 보내고 offline·online 지표를 함께 본다.

케이스 풀이와 답변 예시

최신 정책 3.2절이 검색 top-5에 없고 폐기된 2.8절만 있다면 generation prompt는 hallucination의 유일 원인이 아니다. metadata freshness와 retrieval filter부터 고친다.

오답 표본을 검색·context·생성 단계로 나누고 먼저 최신 문서와 권한 filter가 올바르게 적용됐는지 확인하겠습니다. 검색된 문서가 적절한데 claim이 근거를 벗어나면 답변 claim별 citation과 abstention 기준을 강화하겠습니다. gold set에서 retrieval recall, claim faithfulness, citation correctness와 거절률을 각각 측정하고, 위험도별 허용 false answer 비용을 정한 뒤 canary로 사용자 correction과 escalation도 관찰하겠습니다.

답변에서 드러나는 점: ‘hallucination 줄이기’를 한 prompt 수정으로 해결하지 않고 시스템 단계·지표로 분해한다.

Trade-off

선택얻는 점비용·위험
엄격한 근거 기반 답변근거 없는 주장을 줄이고 감사 가능성을 높인다.자료가 불완전하면 답변 거절과 사용자 불편이 늘어난다.
넓은 context/retrieval관련 정보 누락 가능성을 낮출 수 있다.noise·상충 문서·token 비용이 커지고 모델이 중요한 근거를 놓칠 수 있다.
LLM judge 자동평가대량 regression을 빠르게 비교한다.judge 편향과 자기 선호가 있어 사람 검증과 gold evidence가 필요하다.

흔한 오해

RAG에 citation을 붙이면 hallucination은 사라진다.

citation이 있어도 문장이 그 근거에서 지지되지 않을 수 있다. claim-to-passage entailment와 citation correctness를 평가해야 한다.

직접 풀어보기

예시 풀이와 피드백 보기
