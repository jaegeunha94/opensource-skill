Flexbox 심화 — 축소 예산과 자동 최소 크기

Day 9 overflow를 이어서, 왜 flex: 1만으로 같은 폭과 축소를 보장할 수 없는지 계산한다.

레슨 목록 · 이전 Day 9 · 빠른 참고

면접 질문·상황

긴 상품명이 있는 카드만 넓어지고 삭제 버튼은 화면 밖으로 밀립니다. flex: 1을 줬는데 왜 그렇죠?

가상 관리 화면의 행에는 상품명과 작업 버튼이 있습니다. 면접관은 임의의 width를 추가하는 대신 flex basis·축소·콘텐츠 최소 크기를 구분하는지 봅니다.

전제 개념

Flexbox는 주축의 남는 공간을 나누거나 모자란 공간을 줄입니다. basis는 나누기 전의 출발 크기, grow는 남는 공간을 받을 비율입니다. shrink는 부족한 공간을 줄일 때 쓰지만 basis의 크기를 함께 가중합니다. 그래서 shrink가 둘 다 1이라고 같은 픽셀만큼 줄어드는 것은 아닙니다.

또한 기본 자동 최소 크기는 콘텐츠 때문에 축소를 막을 수 있습니다. row의 텍스트 영역을 줄이려면 min-width: 0과 줄바꿈·말줄임 정책을 함께 정합니다. column의 스크롤 영역이라면 높이 축의 min-height: 0을 확인합니다. 정확한 조건은 CSS Flexbox §4.5에서 확인하세요.

계산으로 답변 구성하기

부모 너비 400px, gap 20px, 두 item의 basis가 300px·200px이고 shrink=1입니다. 패딩·border·최소/최대 제약이 없다는 가정에서 120px이 모자랍니다. 축소 가중치는 300:200이므로 72px·48px을 줄여 최종 228px·152px입니다. 최소 크기에 걸리면 이 계산 결과가 그대로 적용되지 않고 나머지를 다시 나눕니다.

  1. 주축과 실제 가용 공간을 확인하고 gap·padding을 뺍니다.
  2. 각 item의 computed basis·grow·shrink·min/max를 확인합니다.
  3. 텍스트 영역과 작업 버튼의 책임을 나눕니다. 버튼을 줄일지, 텍스트를 줄일지 정책을 정합니다.
  4. 긴 번역·URL·200% 확대·키보드 포커스로 콘텐츠 손실을 검증합니다.
.row { display: flex; gap: 1rem; }
.name { flex: 1 1 0; min-width: 0;
        overflow-wrap: anywhere; }
.actions { flex: 0 0 auto; }

이 예시는 버튼을 유지하고 이름을 줄바꿈하는 정책입니다. 버튼 묶음 자체가 화면보다 크면 줄바꿈이나 다른 배치를 추가해야 합니다.

답변 예시·Trade-off·오해

먼저 행의 주축 가용 폭과 item basis를 확인합니다. 이름의 자동 최소 폭이 축소를 막는다면 min-width:0을 적용하고, 정보가 필요한 상품명은 줄바꿈하겠습니다. 작업 버튼은 축소하지 않되 좁은 화면에서는 묶음을 다음 행으로 옮기겠습니다. DOM의 읽기·탭 순서를 유지하고 확대에서도 접근 가능한지 보겠습니다.

약한 답변: ‘overflow:hidden을 전체 부모에 주면 됩니다.’ 화면 밖 버튼과 포커스까지 숨길 수 있습니다. 말줄임은 높이를 일정하게 하지만 이름 비교를 어렵게 하고, 줄바꿈은 내용을 보존하지만 행 높이가 달라집니다. 두 축의 열 정렬이 핵심이면 Flexbox 줄별 독립 배치보다 다음 Day의 Grid가 더 적합할 수 있습니다.

오해: order로 순서를 바꾸면 접근성 읽기 순서도 바뀐다. 시각 순서만 바꾸므로 논리적인 DOM 순서부터 설계합니다. 명세의 재정렬·접근성 절을 읽으세요.

연습과 피드백

같은 조건에서 gap 없이 가용 폭이 450px이면 300·200 basis는 각각 얼마나 줄어듭니까?

계산 확인

부족한 50px을 3:2로 나눠 30px·20px 축소하므로 270px·180px입니다. 275px·175px은 같은 shrink를 같은 픽셀 감소로 오해한 답입니다. 단, 자동 최소 크기나 min/max 제약이 없다라는 가정을 먼저 말해야 실제 디버깅에도 쓸 수 있습니다.

Follow-up·자기 점검

flex:1과 flex:1 1 auto의 차이는? 출발 basis가 0 계열인지 콘텐츠 기반 auto인지에 따라 분배가 달라집니다. shorthand의 브라우저 계산값과 definite/indefinite 크기도 확인하고, 필요하면 세 값을 명시합니다.

column 내부 목록이 스크롤되지 않으면? 부모 높이 제약, 목록 min-height, overflow 대상부터 봅니다. 주축이 세로이므로 min-width만 바꾸는 것은 근거가 없습니다.
