CSS Box Model — sizing·margin collapse·overflow 진단

width 100%인데 요소가 부모보다 넓어지는 이유는 width가 content box를 뜻할 수 있기 때문이다. 박스 계산을 명시적으로 설명한다.

오늘의 학습 결과: box sizing과 intrinsic minimum이 만드는 overflow를 추적한다

면접 질문

두 열 레이아웃에서 오른쪽 패널이 좁은 화면에서 화면 밖으로 밀립니다. 원인을 어떻게 찾아 해결합니까?

실무 상황: 부모 폭은 800px이고 자식은 `width: 50%`, `padding: 24px`, `border: 1px`다. 내부 flex child는 긴 URL을 포함한다.

왜 묻는가: box model 규칙과 min-content sizing을 연결하고 임의의 width 축소 대신 원인을 고치는지 본다.

전제 개념

기본 `content-box`에서 지정한 width는 content 영역만 의미하고 padding과 border가 추가된다. `border-box`에서는 지정 폭 안에 content·padding·border가 포함된다.

`box-sizing: border-box`만으로 긴 단어, flex item의 자동 최소 크기, grid track overflow가 모두 사라지지는 않는다. 축소 가능한 축과 줄바꿈 정책을 따로 살핀다.

답변 사고 순서

  1. 계산 확인: DevTools computed size와 box model panel에서 content/padding/border 실제 폭을 확인한다.
  2. 상위 제약: 부모의 grid/flex track, gap, padding이 총 폭을 초과하는지 계산한다.
  3. 최소 크기: flex/grid child의 min-content width와 긴 URL·pre/code overflow를 확인한다.
  4. 정책 선택: `min-width:0`, `overflow-wrap:anywhere`, scroll container 중 의미에 맞게 적용한다.
  5. 회귀 확인: 긴 번역 문자열·확대·키보드 포커스에서도 잘림이나 접근성 문제가 없는지 본다.

케이스 풀이와 답변 예시

두 column의 `50% + 48px padding + border`는 부모 폭보다 크다. 전역 `border-box`로 계산을 일관되게 하고, flex item 내부의 긴 URL이 줄어들지 않는다면 그 item의 `min-width`와 wrap 정책을 확인한다.

먼저 computed width와 부모의 gap·padding을 합산해 실제로 어느 박스가 폭을 넘는지 확인하겠습니다. 공통 sizing은 border-box로 맞추되, 내부 긴 URL 때문에 flex child가 최소 폭 아래로 줄지 않는 문제라면 해당 child에 `min-width: 0`과 적절한 wrapping을 적용하겠습니다. 데이터 표처럼 줄바꿈보다 가로 비교가 중요한 콘텐츠는 무리하게 쪼개지 않고 제한된 scroll 영역을 제공하겠습니다.

답변에서 드러나는 점: box sizing 규칙, intrinsic sizing, 콘텐츠 의미를 차례로 확인한다.

Trade-off

선택얻는 점비용·위험
전역 border-box컴포넌트 폭 계산이 예측 가능하고 레이아웃 조합이 쉽다.content 자체의 목표 폭을 정할 때는 내부 usable width를 계산해야 한다.
강제 줄바꿈좁은 화면에서 전체 레이아웃 폭을 지킨다.코드·식별자·표 데이터는 가독성과 복사 경험이 나빠질 수 있다.
가로 스크롤표나 긴 코드의 구조를 보존한다.스크롤 가능성 발견과 키보드·터치 접근성을 고려해야 한다.

흔한 오해

`width: 100%`는 부모의 최종 너비를 넘지 않는다.

content-box에서는 padding과 border가 폭에 더해질 수 있고, flex/grid의 min-content 제약도 최종 폭을 제한한다.

직접 풀어보기

flex child에 `min-width: auto` 상태로 긴 로그 한 줄이 들어와 전체 화면이 넘칩니다. 왜 `min-width: 0`이 효과가 있는지 설명하세요.

예시 풀이와 피드백 보기

flex item의 기본 자동 최소 크기가 콘텐츠의 min-content 크기를 유지해 축소를 막을 수 있다. 0으로 바꾸면 flex 알고리즘이 컨테이너 안으로 줄일 수 있고, 남은 긴 줄은 적절한 wrap/scroll 규칙으로 처리한다.
