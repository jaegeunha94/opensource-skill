Day 10 · 빠른 참고

Compression — 전송량·CPU·캐시 표현의 경계

Day 9 ETag의 표현 구분을 압축 변형에 적용하고, 압축이 이득인 요청을 수치로 고른다.

핵심 판단 기준

  • Accept-Encoding=수신 가능 코딩, Content-Encoding=실제 적용 코딩.
  • 절감 전송 시간 ≈ 절감 바이트/유효 전송률.
  • 추가 CPU 작업 ≈ 요청률×요청당 압축 CPU 시간.
  • Vary/캐시 키와 strong ETag를 코딩된 표현에 맞춘다.

복습용 용어

Representation
코딩·언어 등의 변형까지 포함한 HTTP 자원의 표현.
사전 압축
요청 전에 압축 파일을 생성해 재사용하는 방식.
Compression ratio
원본 크기 대비 압축 후 크기의 비율; 지연 개선과는 구분한다.

다시 확인

  • RFC 9110 §8.4·12.5.3·12.5.5 — Content-Encoding, Accept-Encoding, Vary 의미.
  • Nginx gzip 모듈 — 압축 설정과 HTTPS 압축의 BREACH 경고.
