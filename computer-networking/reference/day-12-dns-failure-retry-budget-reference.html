Day 12 · 빠른 참고

DNS 장애 전파와 클라이언트 재시도 설계

Day 11의 리전 전환을 이어서, DNS 복구 후에도 실패가 남는 이유와 재시도 예산을 계산한다.

핵심 판단 기준

  • NXDOMAIN/NODATA/SERVFAIL을 먼저 구분한다.
  • 권한 응답 → 리졸버 → 앱 캐시 → 기존 연결 순서로 비교한다.
  • 최악 시도 수는 계층별 시도 수의 곱이다. deadline은 대기와 연결 시간도 포함한다.
  • 쓰기 재시도는 멱등 계약과 결과 조회를 확인한다.

복습용 용어

Negative caching
없거나 실패한 DNS 응답을 일정 시간 재사용하는 캐시.
Retry budget
재시도에 허용할 총 횟수·시간·부하의 한도.
Jitter
동시 재시도를 줄이기 위해 대기 시간에 넣는 무작위 분산.

다시 확인

  • RFC 2308 §5 — NXDOMAIN/NODATA의 부정 응답 TTL 기준.
  • RFC 9520 — DNS 해결 실패 캐시와 반복 조회 제한.
  • AWS Builders Library — timeout·재시도 증폭·backoff와 jitter의 운영 설계.
