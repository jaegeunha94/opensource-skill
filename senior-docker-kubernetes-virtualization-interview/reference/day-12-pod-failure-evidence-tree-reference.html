Day 12 · 빠른 참고

운영 Troubleshooting — Pending과 CrashLoop의 증거 분리

Pod 상태를 원인으로 읽지 않고 배치·시작·실행·연결 단계로 진단한다.

핵심 판단 기준

  1. Scheduled와 nodeName → 배치 여부.
  2. Waiting reason/Event → 이미지·볼륨·init 문제.
  3. Last termination + previous log → 앱·probe·OOM.
  4. Ready·EndpointSlice·실제 요청 → 서비스 회복.

복습용 용어

CrashLoopBackOff
반복 종료 컨테이너의 재시작을 늦추는 상태 표시. 근본 원인은 별도 증거로 찾는다.
Pending
Pod 준비가 완료되지 않은 phase. 스케줄링과 시작 단계를 나눠 본다.
last termination
이전 실행의 종료 이유·코드·시간.
readiness
해당 컨테이너가 서비스 트래픽을 받을 준비가 되었는지의 신호.
