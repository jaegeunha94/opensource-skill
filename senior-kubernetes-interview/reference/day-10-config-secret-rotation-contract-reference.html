ConfigMap/Secret — 갱신 전파와 시크릿 회전 계약

설정의 저장·전달·앱 반영을 구분하고 credential 회전을 중단 없이 검증한다.

핵심 판단 기준

  1. 소비 방식별 갱신: env는 교체, volume은 eventual 전달+앱 reload, subPath는 자동 갱신 안 됨.
  2. 신 credential → 전달 → 앱/새 연결 검증 → 옛 연결 drain → 폐기.
  3. 값 대신 비밀이 아닌 적용 버전을 관측.
  4. RBAC·Pod 생성 권한·저장 암호화·로그를 각각 검증.

복습용 용어

ConfigMap
비밀이 아닌 설정을 전달하는 API 객체.
Secret
민감 값을 취급하는 API 객체. 그 자체로 모든 저장/접근 보안이 완료되지 않는다.
eventual propagation
객체 변경이 소비자에게 즉시 동시 반영되지 않고 지연 후 전달되는 특성.
rotation overlap
신구 credential을 제한된 기간 함께 유효하게 두는 회전 전략.
