Day 12 · 빠른 참고

캐시와 페이지네이션 — 신선도·누락·중복 검증

빠른 목록 응답의 의미를 명시하고, 페이지 간 변경을 성능과 함께 시험한다.

핵심 판단 기준

  • live 탐색인지 동일 시점 export인지 먼저 정한다.
  • 정렬 키 변경·삭제·필터·권한 변경을 페이지 경계에서 시험한다.
  • key에는 tenant/접근 범위·필터·정렬·cursor·결과 version을 반영한다.
  • TTL만으로 end-to-end 신선도를 보장하지 않는다.

복습용 용어

keyset
마지막 정렬 값 이후 범위를 읽는 페이지 방식.
snapshot 계약
결과 집합과 내용이 특정 시점/버전과 일치한다는 요구.
materialization
조회 결과를 별도 결과로 생성·보관하는 방식.
stale age
응답 데이터가 기준 최신 상태보다 얼마나 오래되었는지의 시간.

다시 확인

  • PostgreSQL — LIMIT/OFFSET — 예측 가능한 정렬과 페이지 비용의 기본
  • PostgreSQL — Transaction Isolation — statement/transaction snapshot의 차이
