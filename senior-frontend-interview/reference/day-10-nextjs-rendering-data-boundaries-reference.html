Day 10 · 빠른 참고

Next.js 서버 아키텍처 — 공개 상품과 개인 장바구니의 경계

Day 8 상태·Day 9 렌더 비용을 데이터 공개 범위와 서버/브라우저 실행 시점에 연결한다.

핵심 판단 기준

  • Server/Client는 실행 경계, 정적/요청 생성은 시간·재사용 정책.
  • 공개 상품은 재사용, 개인 장바구니는 사용자별 인가·조회.
  • props와 RSC payload에 비밀을 전달하지 않는다.
  • 캐시 모델은 실제 버전·cacheComponents 설정과 명시적 정책으로 확인.
  • TTFB·LCP·상호작용 지연·정확성을 함께 검증.

복습용 용어

SSR
서버에서 HTML을 렌더링하는 방식; 요청 시점 렌더인지 별도 명시한다.
SSG
빌드 등 요청 이전 시점에 정적 페이지를 생성하는 방식.
ISR
정적 결과를 재검증·재생성해 갱신하는 방식.
RSC payload
서버 컴포넌트 결과와 클라이언트 참조·props를 전달하는 직렬화된 데이터.

다시 확인

  • Next.js Server/Client Components — HTML·RSC·hydration의 실행 경계.
  • Next.js 현재 캐싱 안내 — 명시적 캐시·재검증·동적 경계 판단.
  • Next.js 이전 캐시 모델 — Cache Components 비사용 프로젝트와 구분.
  • Next.js 업그레이드 안내 — 프로젝트 버전과 변경 문서 확인.
